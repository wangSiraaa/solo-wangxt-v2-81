# 水库水量平衡教学模拟系统

一个**仅用于教学**的固定时间步水库水量平衡模拟与方案对比系统。
不连接任何真实闸门，演算结果**不替代现实供水调度决策**。

## 教学目标

学员能够：

1. **逐个时段**回答"水库里的水从哪里来、到哪里去"——
   入流、蒸发、生态放水、城市供水、农业供水、弃水如何改变库容；
2. 亲手比较两类用水（城市 / 农业）采用**不同优先级**的两个供水方案；
3. 理解硬约束：**最低生态流量**、**库容上下限（死库容 / 正常蓄水位库容）**；
4. 正确处理三种典型情形：**零来水、超过库容的洪峰、不同单位输入**；
5. 认识到**缺测来水是"缺失"而不是 0**，缺测时段平衡无法闭合。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | FastAPI、SciPy（`interp1d` 水位-库容换算）、NumPy |
| 前端 | Angular 18（standalone components）、Chart.js |
| 数据库 | PostgreSQL（SQLAlchemy；未配置时回退 SQLite 供离线/测试） |

## 逐时段平衡方程

每个固定时间步（内部统一换算为 m³）：

```
S期末 = S期初 + 入流 I − 蒸发 E − 生态放水 R − 城市供水 U − 农业供水 A − 弃水 P
```

**硬条件**（每步都检查）：

- `S_min ≤ S期末 ≤ S_max`（死库容、正常蓄水位库容）
- `R ≥ 生态基流目标`
- 若某时段**即使城市与农业完全不取水**也无法同时满足上述两条 →
  记为**结构性冲突时段**，在结果中列出原因、所需净入流与实际净入流。

**优先级规则**（每时段先保生态基流与死库容，再分剩余可供水）：

- 城市优先：先供城市，余量供农业；
- 农业优先：先供农业，余量供城市；
- 同优先级：按两类需求比例同比例满足。

**弃水**：先用城市/农业取水消落，仍超过库容上限的水量必须弃掉。

**水位**：由给定库容曲线经 SciPy 线性插值得到。

**缺测**：入流为 `null` 的时段所有出流与期末库容输出为 `null`（缺失），
其后时段因状态不可知同样标记为缺失，绝不补零。

## 快速开始

### 方式一：Docker Compose（含 PostgreSQL）

```bash
docker compose up --build
# 前端 http://localhost:4200
# API 文档 http://localhost:8000/docs
```

### 方式二：本地开发

后端：

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 可选：连接 PostgreSQL（不设置则使用本地 sqlite 文件 reservoir.db）
export DATABASE_URL="postgresql+psycopg2://reservoir:reservoir@localhost:5432/reservoir_teaching"

uvicorn app.main:app --reload
```

前端：

```bash
cd frontend
npm install
npm start          # http://localhost:4200，已配置代理到 :8000
```

## 核对样例（每时段水量守恒）

`backend/tests/test_simulation.py` 用三类要求样例逐时段核对，共 15 个测试：

- **零来水**：库容只减不增、供水触碰死库容后变为缺口、残差为 0；
- **超库容洪峰**：弃水量恰好把期末库容顶在上限，且取水能等量减少弃水；
- **不同单位**：`m³/s` × 时长、`万m³`、蒸发 `mm × 水面面积` 三种输入换算一致；
- 缺测显示为缺失、结构性冲突时段报告、两种优先级两方案对比、等权比例分摊、
  API 与 PostgreSQL（测试中为 SQLite）存取往返。

```bash
cd backend && python -m pytest -q
```

每个时段结果都带 `balance_residual_m3`（守恒残差），前端明细表中展示，
正常情况恒为 0（容差 1e-4 m³）。

## 使用流程（课堂建议）

1. 打开内置 **7 日教学样例**（含零来水、洪峰、一处缺测）；
2. 进入 **逐时段问答**：先填本时段"入流/生态放水/城市/农业/弃水/期末库容"，
   再揭晓与引擎对照，复述水的来源与去向；
3. 查看逐时段库容-水位过程线与取水/缺口堆叠柱状图；
4. 切换**城市优先 / 农业优先**两个方案，在对比表中观察缺口由谁承担；
5. 修改参数（如把生态基流调大、把死库容抬高）制造冲突，
   阅读"找不到可行方案"面板指出的具体冲突时段；
6. 保存场景到 PostgreSQL，供下节课载入。

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/simulate` | 直接模拟（1–2 个方案），不落库 |
| POST | `/api/scenarios` | 保存场景 |
| GET | `/api/scenarios` | 场景列表 |
| GET | `/api/scenarios/{id}` | 场景详情 |
| POST | `/api/scenarios/{id}/simulate` | 对已保存场景做模拟 |
| DELETE | `/api/scenarios/{id}` | 删除 |
